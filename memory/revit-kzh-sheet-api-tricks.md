РМЦ КЖ пилотында (РМЦ-КМ.rvt, БК_КМ шаблоны, Revit 2025) тексерілді, генераторлар `D:\_claude_work\RMC\kzh\kz30…kz36`:

- **ViewSection.CreateSection:** көрініс +BasisZ бағытына ҚАРАЙДЫ, кесу жазықтығы Min.Z-те, алыс шекара Max.Z-те, оң жақ = −BasisX (BasisY = жоғары). Көлденең (төмен қарайтын) разрезді Revit 180° бұрып жібереді → up/right-ты керісінше беріп сұра, жасалған соң View.RightDirection / UpDirection тексер.
- **Размер тірек сызықтары кадр ішінде болсын:** көрінбейтін detail line модель кадрынан тыс болса, размер көрінбейді (жоғалады) → кадрды тізбектерге дейін үлкейт.
- **БК_типовая_аннотация_текст_с_выноской:** кірістіру нүктесі = полка ортасы. Выноска ұшы полканың x-аралығына түссе, Revit оны полка ұшынан емес, астыңғы ортадан іледі (полкадан «жетім» қиғаш сызық шығады). Ереже: ұш полка аралығынан тыс тұрсын, Elbow = жақын ұштан 1,2 мм сыртта, полка биіктігінде; артық әдепкі выносканы `removeLeader()` арқылы алып таста.
- **Ссылочный разрез «по1»:** «Метка связи» — разрез ТИПІНІҢ параметрі (дананікі read-only) → тип көшірмесі «КЖ_разрез_ссылка», VIEWER_REFERENCE_LABEL_TEXT = "", ChangeTypeId. Бағыт head/tail ретімен анықталады — қате болса ұштарын ауыстыр.
- **Grid ұзындығы әр көріністе:** `GetCurvesInView(ViewSpecific)` → қисық сызығына проекциялап `SetCurveInView`, шеңбер бір ұшта (`ShowBubbleInView/HideBubbleInView`), әйтпесе viewport қорабы ось ұзындығынан үлкейеді.
- **Кесте:** ViewSchedule.Split(n) → `ScheduleSheetInstance.Create(…, segmentIndex)`; қайта іске қосқанда `IsSplit()` тексер. Сурет бағаны (Изображение формы) жол биіктігін сурет арақатынасымен үлкейтеді (40,7 мм баған → ~28 мм жол). FormatOptions(UnitTypeId.Fixed) + Accuracy (Number параметрге General қате береді). Көп санатты кестеде HOST_VOLUME_COMPUTED жоқ.
- **BI шаблон кестелері БК негізді файлға көшпейді:** CopyElements «m_big2SmallMap2 duplicate entries» — файлда шаблондағы BI параметрлердің аттастары басқа GUID-пен тұрса (РМЦ-та 31). Жаңа бос құжатқа көшеді, бірақ одан әрі де көшпейді. Шешім: кесте пішінін (бағандар, ендер, header торы) өз файлында жасау, деректер тұрақты ФОП-тағы КЖ_* параметрлерінен.
- **Жоспардағы разрез белгісі (BI «(типовая_аннотация)разрез_условный», Касымова 16.11):**
  - кірістіру нүктесі — бірінші штрихтың ортасы;
  - «Длина» = ұштар арасы (қағаз мм) − 8,2;
  - нұсқар штрихқа FacingOrientation бағытымен қарайды (= разрездің қарау бағыты), нұсқар мен нөмір штрихтың қарсы жағында тұрады.
  - Тік белгі: 90°-қа бұр (`ElementTransformUtils.RotateElement`, ось Z) және «Вертикальный»=1 — нөмір тік тұрады (шаблонның «(Вентблоки)Узлы А, Б» парағындағыдай).
  - Ұшы ось шеңберіне тисе — қатардан тыс шығар. Тік белгі парақ атауына тисе — атауды көтер.
  - Генератор: `D:\_claude_work\Kasymova\revit\k10_scheme.cs` (`secs=`), разрез парағы `k11_section.cs`.
- Қате терезесі (failure dialog) API жұмысында шықса — UIAutomation-мен «Отмена»; Revit уақытша құжатты белсенді етіп тастауы мүмкін → `OpenAndActivateDocument(негізгі.rvt)`, сосын уақытшасын `Close(false)`.

- **Көлденең разрездің КРОПЫ да айналады (16.11, РМЦ):** Sec(u0,u1,v0,v1) сұрасаң, нәтиже x = CX−u1…CX−u0, y = CY−v1…CY−v0. Пилоттың 3-3-інде осыдан екінші размер тізбектерінің тірек сызықтары кропқа кірмей, тізбек мүлде көрінбеді → кропты осы формуламен есепте, жасалған соң View.Origin-ді тексер.
- **Аннотация кадры (annotation crop) шекарасын кескен аннотация МҮЛДЕ жасырылады** (выноска, размер). Тексеріс: `kz56_annocheck.cs` — көріністің әр аннотациясының get_BoundingBox(view) == null → көрінбейді (TOTAL 0 болсын).
- **БК_обрыв** (типовая аннотация): қорабы ±150 мм қағазда (в000…в149 жасырын сегменттері есепке кіреді) → кадр қосулы көріністе ешқашан көрінбейді. КМ көріністеріндегідей кадрды өшір, бірақ композициядан КЕЙІН: кадр өшкенде viewport қорабы ±150 мм үлкейеді (GetBoxOutline-ға сүйенген орналастыру бұзылады), ал мазмұн мен атау орнында қалады (kz61 сынағы). Кірістіру нүктесі — символдың ОРТАСЫ, «Длина» — қағаз мм.
- **Кесте сегменттерін теңестіру:** `ViewSchedule.SetSegmentHeight(0, h)` — жол келесі сегментке ауысады; 5 мм қадаммен ең төменгі шегі ең жоғары биіктікті таңда (соңғы сегмент биіктігі ∞).
- **Шпилька эскизі:** Revit автопішіні «Форма арматурного стержня 1» суретсіз, REBAR_SHAPE_IMAGE ro → шаблонның «(форма)шпилька» пішінін дананың REBAR_SHAPE параметрімен бер (ілгек 180° «Стандартный сейсмический» өзі ауысады) — ВД-да эскиз шығады; ұзындығы әртүрлі шпилька — Шп1/Шп2 бөлек позиция.
- **Бір позиция — бір ұзындық:** пішіні мен эскиз өлшемдері бірдей стерженьдердің Revit ұзындығы дөңгелектеуден 10 мм айырылса (2300/2310) — үлкенін ал (kz33 `grpL`).
- **Семейство данасының қырына размер (16.11, КЖ-2.2):** `GeometryInstance.GetSymbolGeometry()` бетінің Reference-ін ал (координатасы `gi.Transform.OfPoint`). `GetInstanceGeometry()` сілтемесі семейство координатасына қатысты — размер «850 | 5575» деп қате шығады, тізбек сегменттері ығысады. Тізбек сегменттерінің ортасы/ұзындығын өз тізіміңнен емес, `DimensionSegment.Origin/Value`-дан ал (сынақ `kzh\kz74_reftest.cs`).
- **Парақ параметрін атымен көшірме:** штамп данасында да «Номер листа» (SHEET_NUMBER) бар → `LookupParameter(name).Set` жаңа парақтың нөмірін ауыстырып, «Номер листа уже используется» модаль терезесін шығарады (FailuresPreprocessor ұстамайды). Тек BuiltIn ЕМЕС параметрді көшір. Терезе өз данамда болса — `PostMessage(dlg, WM_COMMAND, 3, btn)` («Отмена»).
- **Жалпы өлшем мәтіні ортаңғы оське түседі** (60000 → 6 осі, 36000 → D) — мәтінді көрші аралық ортасына жылжыт (kz71 Chain).
- **Размер мәтінінің геометриясы (БК_основной_2,5мм, PNG пикселімен калибрленген, 16.11):** `DimensionSegment.TextPosition` = мәтіннің АСТЫ; глиф TP-дан өз «жоғары» бағытына 1,0…3,5 мм (көлденеңде +Y, тікте −X), жартылай ұзындығы таңба × 0,8 мм. Жылжытылған мәтіннің выноскасы «От начала»: сегмент ортасынан (`Origin`) иықтың жақын ұшына (`LeaderEndPosition`, TP-дан 0,3 мм). Төмендегі көлденең тізбекте иық мәтіннің СЫРТЫНДА → бір қатарда тұрған екі көтерілген санның сыртқысының выноскасы ішкісін кеседі (drawing-checker ұстады, менің ескі тексерісім — жоқ). Шешім: «саты» — ішкі сан 10 мм, сыртқысы 6 мм (әр саты 4 мм). Тік (сол жақтағы) тізбекте иық мәтіннің ішінде — бір биіктік жеткілікті. Тексеріс `kzh\kz73_check22.cs` (выноска×мәтін санағы бар).

- **Ссылочный разрез маркері (Касымова, 17.11.2026):** `ViewSection.CreateReferenceSection(doc, planId, secViewId, head, tail)` — қарау бағыты = Z × (tail − head); типін «разрез_без_номера_листа_ссылка»-ға ауыстыр; нөмір = разрез видінің Viewport detail number. Маркердің екі жуан ұшы әрқайсысы ~13 мм (қағазда): қысқа сызықта бірігіп кетеді. Разрез виді өшірілсе маркер де өшеді. Блок-белгі («разрез_условный») қолданылмайды — [[project-kasymova-hotel]].
- FilledRegion шекарасы шын көрінбейтін: `FilledRegion.GetValidLineStyleIdsForFilledRegion` ішінен `GraphicsStyleCategory.Id == OST_InvisibleLines` (РМЦ-да id 621). Аттас «<Невидимые линии>» id 195 — жасыл үзік, көрінеді (17.11).
- GA выноскасын алып тастау: `AnnotationSymbol.removeLeader()` (кіші әріппен; `RemoveLeader` жоқ).
