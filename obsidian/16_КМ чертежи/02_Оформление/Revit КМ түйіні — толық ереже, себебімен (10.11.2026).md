## 1. Пайдаланушы сызбасын оқу (геометрия дәл көшіріледі)

1. Түпнұсқа DWG-ға тиіспеймін: көшірмесін алып, `accoreconsole` арқылы `DXFOUT` (скрипт cp1251), сосын `ezdxf`.
2. Түйін парағын сипатты размерлер арқылы табамын (`dxf_find.py`), аймақты JSON-ға шығарамын (`dxf_node4.py`), әр көріністі осьтен есептелген миллиметрмен басып шығарамын (`dump_view.py`).
3. Әр бөлшекке кесте: қалыңдығы, контур нүктелері, болт саны/қадамы, қай бетке пісірілгені, арасындағы саңылау.
   - *Себебі:* суреттен көзбен өлшеу қате береді; пайдаланушы әр сызықты өз сызбасымен салыстырады.
4. Сызбаның өз ішінде қайшылық болса (размер 291, сызылғаны 300) — **размер жазуы** басым, қайшылық есепте аталады.
5. Профиль басқа болса: **балка жағы 1:1 көшіріледі**, **колонна жағы сол принциппен жаңа өлшемге келтіріледі** (накладка ені = колонна полкасының ені; оголовок алыс полкадан 20, жақын бетінен 6 асады; қабырға полка ұшына дейін, фаска ≥ r). Өзгерген өлшемдер тізіммен беріледі.
6. Сол ғимаратқа ғана қатысты бөлшектер (прогон, связь, еңіс) түйінге өздігінен қосылмайды — пайдаланушы айтса ғана.

## 2. Модель (Revit 2025)

- **Файл:** `БК_КМ.rte` шаблонынан, аты `БК-КМ_Узел_<колонна>-<балка>[_түрі].rvt`, папка `Узлы_КМ`.
- **Координата:** колонна осі — басы; полкалары Y-ке перпендикуляр; балка +Y бойымен; балка үсті z = 0. *Себебі:* барлық скрипт, аудит, размер осы жүйеде жазылады.
- **Прокат:** `(КМ)двутавр_ГОСТ57837_*` семействолары, тип жоба ішінде стандарт өлшеміне келтіріледі; аудит қима ауданын кестемен салыстырады (r қате болса бірден көрінеді).
- **Пластина, уголок, прогон:** пішіні тікбұрыш болмаса — DirectShape (категория «Соединения несущих конструкций» / «Каркас несущий»), атауы «ПЛ1 накладка верхняя -16», маркасы Mark-та. Атауда `[` болмайды.
- **Тесіктер:** d + 3. Колонна/балка — бос цилиндр семействосымен (`БК_отверстие_dNN`, InstanceVoidCut); пластина — эскизінде шеңберлері бар дене. *Себебі:* «Соединения…» категориясын жобада void кеспейді.
- **Болттар:** «Болты» категориясы, әр болт бір дене (шайба + бас + стержень + шайба + гайка біріктірілген). Ұзындық = пакет + 2 шайба + гайка + 1–2 виток.
- **Шовтар:** «Сварные швы» категориясы, үшбұрышты призма, катеттері беттердің бойымен. Әр түйіскен жиекте шов; контур тұйық; қол жетпейтін жерге шов салынбайды; қабаттасатын шовтар бір денеге біріктіріледі.
- **Ереже 5:** элемент ұшы тірелетін бетке 0,3 мм жетпейді (мерцание болмасын), саңылау шов астында.
- **Элементтер — қысқа кесінді:** колонна, балка, прогон парақта обрыв тұрған жерде бітеді. *Себебі:* тірі разрез белгісінің басы элементтен тыс, подрезканың ішінде тұруы керек (§4.3).
- **3D көрініс:** «КМ 3D Узел 1», 1:10, Fine, материалдар күңгірт (Shininess 0). Пайдаланушы «әдемі» деген соң оған тиіспейміз.
- **Есеп жоқ болса** — қалыңдық/болт/катет конструктивті: қабырға t ≥ 2·b·√(Ry/E); катет СП 16.13330 табл. 38 минимумынан кем емес; шет ≥ 1,5·d₀, қадам ≥ 2,5·d₀ (табл. 40). Сызбадағы мән нормадан кіші болса — сызба сақталады, бірақ ескертіледі.

## 3. Тексеріс (көрсетпес бұрын)

1. Өз аудитім (`uz_18_audit_nakl.cs` үлгісі): қиылысу жоқ (барлық жұп), әр жиекте шов, материал/категория, әр болт осінде тесік, bbox пен аудан, 0,3 мм саңылау жабық, шов шыңдары бетте, бір бағытты қабаттасқан беттер жоқ → **ALL PASS**.
2. Тәуелсіз тексеруші (бөлек агент, өз зондтарымен, сызбамен бөлшек-бөлшек салыстырады). Оның әр FAIL-ы түзетіледі; түзетілмегені есепте аталады.
3. Жақын суреттер (6–8 бағыт) көзбен қаралады.
- *Себебі:* аудит менің ойлаған нәрсемді ғана тексереді; тәуелсіз көз шов қабаттасуын, жинау мүмкін еместігін, нормадан ауытқуды тапты.

## 4. Парақ (оформление) — әр элемент және себебі

### 4.1 Парақ пен көріністер
- Құрамы пайдаланушы парағындай: **Узел + Разрез 1-1 + 2-2 + 3-3**, бәрі **1:10**, бір парақ — бір масштаб.
- Көріністер — модельдің **тірі разрездері** (сызылған сурет емес). *Себебі:* модель өзгерсе парақ өзі жаңарады.
- Көлденең разрез: `ViewSection.CreateSection`, BasisZ = −Z; 180° бұрылып шығады, сондықтан right/up теріс беріледі.
- Режим «Скрытые линии», детализация «Высокая». Подрезка модельден кең, **рамкасы көрінбейді** (пайдаланушы: «шетіндегі қара сызықтар көрінбесін»).
- **Түстер:** әр бөлшек 3D материалының реңкімен ашық боялады, контуры қоюырақ (элемент override). Колонна қызыл, балка күлгін-қызғылт, пластиналар көгілдір, прогон сарғыш, болттар сұр. *Себебі:* пайдаланушы түсті көруді сұрады; сызық пен жазу оқылуы үшін бояу ашық.
- Орналасу: бірінші қатар Узел + 1-1, екінші қатар 2-2 + 3-3, штамп үстіндегі бос орында **3D сурет** (тақырыпсыз viewport).
- Штамп `БК_штамп`. Шаблонда альбомдық А3 жоқ — әзірге А3 книжный.

### 4.2 Тақырыптар
- Разрездер: «Разрез N - N», көріністің үстінде ортада (Viewport.LabelOffset).
- Түйін: мәтін емес, **шеңбер** (`БК_узел_круг`): үстінде нөмір, астында түйін белгіленген схема парағы — пайдаланушы қолмен жазады. *Себебі:* пайдаланушы альбомындағы «4/12» белгісі.

### 4.3 Разрез белгілері
- **Тірі болуы керек:** басын екі рет басқанда разрез ашылады; сызығы, ұштары, бағыты өзгереді.
- Белгінің басы разрездің шетінде тұрады → шеті элементтен тыс әрі түйін көрінісінің подрезкасы ішінде болуы шарт; подрезка шетіндегі баста ұстағыш болмайды.
- **Нөмір стрелканың жанында** (штрих ұшында емес): `БК_марка_разрез` ішінде «Номер вида спереди/сзади» лейблдері ортаға тураланып, (−1,5; ∓8,5) нүктесіне қойылған; тег: басы «спереди», құйрығы «сзади».
- **Бүйірінен көрінетін тік разрез (1-1):** тірі белгісі екі ұшына бірдей символ қояды, нөмірі бір ұшында қарсы жаққа түседі. Сондықтан түйін көрінісінде оның орнына **сілтеме-разрез** (`CreateReferenceSection`) тұрады: нөмірі өзінде, екі рет басса 1-1 ашылады, ұштары еркін жылжиды. Типінің «Метка ссылки» өрісі бос; стрелка бағыты бас/құйрық нүктелерінің ретімен беріледі.
- Разрез нөмірі = viewport-тың «Номер вида» (1, 2, 3); түйін көрінісі «У1».

### 4.4 Размерлер
- Тип `БК_основной_2,5мм` (ISOCPEUR 2,5, засечка).
- Тізбектер: колонна ені (ось арқылы), болт қадамдары (шет/қадам/шет), пластина өлшемдері, жалпы ұзындық — пайдаланушы парағындағы тізбектердің дәл өзі.
- **Алшақ:** параллель тізбектер арасы ≥ 8 мм, контурдан ≥ 10 мм; ұсақ тізбек ішке, жалпысы сыртқа.
- Куә нүктелері — «<Невидимые линии>» стиліндегі 6 мм detail сызықтар. *Себебі:* DirectShape беттері тұрақты сілтеме бермейді.
- Ось сызықтары — «<Осевая линия>».

### 4.5 Выноскалар (СПДС выноскасынан аумайды)
- **Түрі:** жіңішке полка мәтіннің бүкіл еніне (ұзын жол + 1,5 мм екі жағынан); 1-жол полка үстінде, 2-жол астында; сол жіңішке сызық полканың **стрелкаға қараған ұшынан** элементке барады; сызық үзілмейді, қалыңдығы бірдей; стрелка жіңішке ашық (`БК_стрелка_открытая_3,5мм_20°`). «Болты …» жазулары стрелкасыз.
- **Мазмұны:** маркалы элементке тек марка (К1, Б1, П1); маркасыз бөлшекке «-t16 / С245», «L 100x7 / С245».
- **Мінезі:** жазу + полка + сызық бір нысан; жазуды қозғағанда сызықтың сол ұшы бірге жүреді, стрелка ұшы бөлек жылжиды.
- **Жасалуы:** `БК_типовая_аннотация_текст_с_выноской` («Текст верх», «Текст низ», «Ширина полки»). Оның выноскасындағы сынық нүктесі бос нүкте болғандықтан, **`BKLeaderShelf` қосымшасы** символ өзгерген сайын сынықты полка ұшынан 1 мм жерге қояды.
- *Неге басқаша емес:* мәтіннің асты сызығы шрифт қалыңдығында және тек 1-жол енінде шығады; тег пен кәдімгі аннотацияда сынық орнында қалады — үшеуін де пайдаланушы қабылдамады.
- **Орны:** жазу өз элементінің қасында; бір-біріне, размер тізбегіне, разрез белгісіне тимейді; сызбаны мүмкіндігінше кеспейді.
- **КМ-де стрелка бар; КЖ-да стрелка жоқ** (засечка) — пайдаланушы шешімі 10.11.

### 4.6 Шовтар парақта
- Парақ көріністерінде модельдегі шов денелері **жасырылады** (3D-да қалады); орнына шартты белгі:
  - **заводской шов** — жиек бойымен штрихтар, биіктігі 1,5 мм, қадамы 1 мм, семейство `БК_шов_заводской`;
  - **монтажный шов** — крестиктер 0,9 мм, қадамы 1,2 мм, семейство `БК_шов_монтажный`;
  - **көлденеңінен көрінетін шов (бұрышта)** — қара тұтас үшбұрыш, катеті қағазда 1,5 мм, шов жағында — аннотация семействосы `БК_шов_угол` (басы тік бұрышта, 0/90/180/270° бұрылады; `uz_43_weld_corner_family.cs`). *Себебі:* көріністе сызылған маскасыз тұтас область (`БК_шов_сечение`, IsMasking = false) түсті бөлшектің үстінде қуыс шығады — модель түсі бояуды жауып қалады; семейство ішіндегі тұтас область әрдайым маскалаушы, сондықтан қара болып тұрады.
- **Шов белгісінің сызығы жіңішке — 0,05 мм** (пайдаланушы 10.11: «сызықтардың толщинасын 0,05 мм қыл, жіңішке болып көрінуі тиіс»). Сондықтан белгі **мәтінмен («IIIII», «ххххх») жасалмайды** — әріптің сызығы шрифт қалыңдығында шығады, оны жіңішкерту мүмкін емес. Белгі — нағыз сызықтардан тұратын аннотация семействосы, сызықтары «БК_шов_линия» ішкі категориясында, перо 1 (шаблонның ең жіңішке пероcы).
- Әр жиекке бір дана: басы — шовтың басы, белгілер +X бойымен, дана параметрі **«Длина»** (қағаздағы мм). Семействода 150 белгі бар, әрқайсысы `Длина > шаг_1мм × x` формуласымен көрінеді — ұзындықты өзгертсе белгі саны өзі өзгереді, дана біртұтас жылжиды/бұрылады. Скрипт: `uz_42_weld_families.cs`.
- **Қайсысы заводской / монтажный** (пайдаланушы 10.11 растады: «Ия дұрыс»)**:** монтажда — балка накладкалар арасына қойылған соң пісірілетіндер (үстіңгі накладка ↔ колонна, накладкалар ↔ балка); заводта — колонна қабырғалары, астыңғы накладка мен кронштейн ↔ колонна, стенка пластинасы мен уголок ↔ колонна, прогон пластинасы мен қабырғасы ↔ оголовок. Бөлінуі әр түйінде жинау ретінен шығарылады және пайдаланушыға көрсетіледі.
- Пландарда пластина астында жасырын қалатын шовтар көрсетілмейді.

### 4.7 Обрыв
- Элемент кесілген жерде `БК_обрыв` (ортасында зигзагы бар жіңішке сызық, дана параметрі «Длина»): колонна асты, балка ұшы, прогон ұштары.

### 4.8 Семейство тізімі (қайта қолданылады)
`БК_узел_круг`, `БК_обрыв`, `БК_марка_разрез` (өзгертілген), `БК_типовая_аннотация_текст_с_выноской` + типі `БК_выноска_стрелка`, `БК_знак_разреза` (қосалқы, тірі белгі болмайтын жерге), `БК_отверстие_d23/d27`, `БК_шов_заводской`, `БК_шов_монтажный` (сызықты аннотация, «Длина»), `БК_шов_угол` (бұрыш үшбұрышы); ескі область типі `БК_шов_сечение`.
- *Ереже:* қайталанатын әр белгі — семейство не тип, кейін өзгерту оңай болуы үшін.

## 5. Жұмыс тәртібі
- Пайдаланушы сол Revit-те қатар жұмыс істеп отырса — көрініс пен парақты қайта жасамаймын, **тек орнында өзгертемін**; әр үлкен өзгеріс алдында .rvt көшірмесі алынады.
- Өз Revit данамды іске қосқанда: pyRevit диалогы — «Не загружать» (тұрақты сенім бермеймін), өз қосымшам — «Загрузить один раз». Тұрақты қосымша орнату — тек пайдаланушы рұқсатымен.
- Нәтиже тек жоба папкасына таза атпен; Revit бэкаптары (`*.000N.rvt`) корзинаға.
- Әр кезеңнен соң парақ суреті экспортталып қаралады; кемшілік есепте жасырылмайды.

## 6. Revit API бойынша табылғандар (қайталамау үшін)
- API лейбл жасай алмайды: бар семействоның .rfa көшірмесін ашып өзгерту (RenameParameter, CopyElement, MoveElement).
- Аннотация семействосында NewReferencePlane жоқ: размер сызық ұштарына (GetEndPointReference), flex-пен тексеру.
- Айналдырылған символдың мәтіні де айналады → бағыттар типпен беріледі.
- Типовая аннотация выноскасының анкері — символ жағының сынық нүктесіне ең жақын ортасы.
- Разрез белгісіндегі мәтін геометриямен бірге айналмайды (айналық қолданылмайды) — сондықтан бас/құйрыққа әртүрлі лейбл.
- Мәтін енін `TextNote.Width`-пен өлшеу (bounding box 0 береді — шов белгілері бүкіл параққа созылып кеткен).
- DirectShape атауында `[` болмайды; face-based шаблонда өз хост экструзиясы бар.
- BEKA-1-де Revit-ті RBLive + Roslyn runner (`runner.cs`, `run.ps1`) арқылы жүргізу; BEKA-2-де MCP bridge.
