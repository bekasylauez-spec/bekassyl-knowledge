# ЧЕРТЕЖ ЖҮЙЕСІ — кез келген сессия осыдан бастайды

Жазылған: 11.11.2026. Источник: пайдаланушы — «Клаудта кез келген сессияда чертеж жасайтын болса бірден GitHub-тан оқып, қалай жасалуы керек системасын тауып оқитын ереже жаса».
Бұл файл екі жерде бірдей тұрады: GitHub `bekasylauez-spec/bekasyl-kzh-km` → `_Стандарт_КЖ\00_ЧЕРТЕЖ_ЖҮЙЕСІ.md` және Obsidian `Bekassyl\00_ЧЕРТЕЖ ЖҮЙЕСІ — осыдан баста.md`. Біреуін өзгертсең — екіншісін де өзгерт.

## 0. Әр чертеж жұмысының алдында (міндетті)

1. Стандартты жаңарт: `powershell -NoProfile -ExecutionPolicy Bypass -File "D:\РАБОЧКА\.claude\std-pull.ps1"` (BEKA-2-де `R:\.claude\std-pull.ps1` не `\\BEKA-1\РАБОЧКА\.claude\std-pull.ps1`). Ол `STD_ROOT=` (стандарт папкасы), `INDEX=` (осы файл), `STATE=`, `COMMIT=` жолдарын шығарады.
2. `STATE` OK болмаса — жергілікті/кэштегі нұсқамен жұмыс істе, бірақ пайдаланушыға «стандарт жаңартылмады» деп айт.
3. Пайдаланушы аналог берсе — алдымен **5-бөлімді (Аналог ережесі)** оқы.
3а. Төмендегі 1-кестеден жұмыс түрін тап, көрсетілген файлдарды **сол ретпен** оқы. Не оқығаныңды қысқа айт.
4. Жұмыс біткенде жаңа ереже шықса — 3-бөлім бойынша жаз да GitHub-қа жібер.

`STD` = `STD_ROOT` (GitHub, пайдаланушы бекіткен ережелер — басым). `OBS` = `D:\РАБОЧКА\Bekassyl` (Obsidian). `БАЗА` = `D:\РАБОЧКА\База_КМ`. `УЗЛЫ` = `D:\РАБОЧКА\Узлы_КМ`.

## 2. Басымдық (қайшылық болса)

1. Пайдаланушының осы чаттағы сөзі.
2. `STD` (GitHub): `ЕРЕЖЕЛЕР.md`, `КМ_ҚАТЕЛЕР_ПРОМПТ.md`, `КМ_стандарт\`.
3. Obsidian `Bekassyl` + `~/.claude/CLAUDE.md` + memory.
4. Пайдаланушы шаблоны мен жоба аналогы (стиль, парақ реті).
5. `БАЗА` аналогтары (тек конструктив, стиль емес).
Екі ереже қайшы келіп, қайсысы кейінгі екені анық болмаса — пайдаланушыдан сұра.

## 3. Жаңа ереже шыққанда (пайдаланушы түзетсе)

1. Қатенің бір нүктесін емес, бүкіл түрін түзет.
2. Жаз: `STD\ЕРЕЖЕЛЕР.md` (келесі № нөмірмен, пайдаланушы сөзімен), КМ болса `STD\КМ_ҚАТЕЛЕР_ПРОМПТ.md` және `STD\КМ_стандарт\` тиісті файлы, чек-листке (`06`) жаңа тармақ; Obsidian тақырып жазбасы; memory.
3. Revit-те түзетілген узел ережесі DWG-ға да қолданылады (№62), 3D-ден басқасы.
4. GitHub-қа жібер: BEKA-2-де `D:\Бекасыл КЖ КМ` ішінен commit + push; басқа компта кэштен (`%LOCALAPPDATA%\bekassyl-std`) тек `_Стандарт_КЖ` файлдарын өзгертіп commit + push. Push алдында `git pull`.
5. Осы индекске жаңа файл/бөлім қосылса — 1-кестені жаңарт (екі көшірмесін де).

## 4. Желі не GitHub жоқ болса

Кэш (`%LOCALAPPDATA%\bekassyl-std\_Стандарт_КЖ`) не BEKA-2-дегі жергілікті папка оқылады; ол да жоқ болса — Obsidian `Bekassyl` (`16_КМ чертежи`, `01_Общие правила`, `14_Мои правила`) және memory. Бұл жағдайды есепте айт.

## 5. Аналог ережесі (пайдаланушы аналог берсе)

Источник: пайдаланушы 11.11.2026 — «бір аналог бергенде дәл сол аналогпен өз чертежін корректировка жасап, уклон, сечениені архитектурадан алып, узелді өзіне келтіре алатындай әдемі чертеж шығарсын. Басқа жақтан болмайтын бір затты алып, қуып қате жасайды. Чат бірінші берілген аналог бойынша; жетпесе GitHub-тан қарауы міндетті; ол жақтан таппаса менен сұрауға міндетті».

### 5.1 Дереккөз реті (қатаң, аттап өтуге болмайды)
1. **Берілген аналог.** Парақ құрамы, реті, узел құрылымы, стиль — дәл содан. Басқа объектінің шешімін араластырма.
2. **GitHub стандарты** (`STD`: `ЕРЕЖЕЛЕР.md`, `КМ_стандарт\`, `КМ_ҚАТЕЛЕР_ПРОМПТ.md`) және сонда көрсетілген базалар (`БАЗА`, Obsidian) — тек аналогта жоқ не аналогта қате нәрсе үшін.
3. **Пайдаланушыдан сұрау.** Екеуінен де табылмаса — тоқта да сұра: не жетпейді, қай парақ/узел, қандай нұсқалар бар.
Тыйым: интернеттен, серияның жалпы шешімінен, «өз стандартымнан», басқа жобадан өз бетімен алу; жоқ нәрсені ойлап табу. Мұндай көз тек пайдаланушы рұқсат бергенде қолданылады.

### 5.2 Аналогтан не алынады, не алынбайды
| Аналогтан алынады (өзгермейді) | Өз жобадан алынады (аналогтағы мән ауыстырылады) |
|---|---|
| Парақтар тізімі мен реті, парақ композициясы | Осьтер, пролёт, шаг, отметкалар — **АР** |
| Узелдің құрылымы: қандай пластина, қабырға, болт, шов, не неге бекітілген | **Уклон (еңіс)** — АР (кровля), ЛИРА-мен қайшы болса сұра |
| Видтер мен разрездер жиыны, размер тізбектерінің түрі | **Сечение** — өз жобаның сечениесі (ЛИРА / ведомость элементов; АР-да көрсетілсе АР-мен салыстыр) |
| Выноска, размер, штамп, кесте стилі | Ойықтар, қабырға, кровля, ж/б жанасуы — АР |
| Ескертпелер мәтінінің құрылымы | Күштер, шарнир/қатаң — ЛИРА; анкер, фундамент үсті — КЖ; кран — ТХ |

### 5.3 Корректировка тәртібі (әр парақ, әр узел)
1. Аналог парағын ашып қара (plot/PNG, жақындатып) — не тұрғанын тізіп жаз.
2. «Аналогта → менде» кестесін жаса: әр элемент пен бөлшекке аналогтағы мән, өз мәнім, көзі (АР парағы / ЛИРА / КЖ). Көзі жоқ жол — сұрақ.
3. **Геометрияны келтір, тек мәтінді емес:** сечение өзгерсе — профиль биіктігі, полка ені, пластина өлшемі, болт өрісі, саңылаулар қайта есептеледі; уклон өзгерсе — қиғаш кесулер, фасонка бұрышы, прогон тірегі, отметкалар қайта есептеледі.
4. Аналогта бар, менде жоқ элемент (мыс. кран, площадка) — алынып тасталады; менде бар, аналогта жоқ — 5.1 ретімен ізделеді.
5. Аналогтың өз қатесін көшірме (парақтар арасындағы қайшылық, басқа жобадан қалған мәтін) — байқасаң айт.
6. Көрсетпес бұрын өз парағыңды аналог парағының қасына қойып салыстыр: құрамы бірдей, өлшемдер өзімдікі; парақта аналогтың бірде-бір саны, маркасы, отметкасы қалмаған (мәтінмен іздеп тексер).

### 5.4 Сұрақ қою үлгісі
«Узел N: аналогта (парақ X) ___ бар, менің жобамда ___ . GitHub стандартында (файл) табылмады. Нұсқалар: (а) … (б) … Қайсысы?» — бір хабарламада бәрін жина, жұмыстың қалған бөлігін тоқтатпа.
